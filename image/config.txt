# Serial UART options for HAT and onboard Bluetooth
#
# The original Avnet (Linux 4.14) vendor block is kept verbatim
# below for reference. On this 6.18 stack ALL FOUR vendor options
# are reproducible (verified on the board 2026-10-15): the UART
# roles are fused into the device tree at compile time, so options
# are selected by swapping the device_tree main line - never by
# enabling the vendor overlay lines.
#
#   * option 0 (BT on ttyAMA0/PL011, no HAT UART):
#       device_tree=bcm2710-rpi-custom-btpl011.dtb
#     (replace the main device_tree line; keep enable_uart
#     commented - the firmware keeps the mini-uart disabled when
#     it carries nothing, matching stock option 0)
#   * option 1 (option 0 + ttyS0 mini-uart for the HAT on
#     GPIO14/15 = /dev/serial0, console, core clock locked):
#       device_tree=bcm2710-rpi-custom-btpl011.dtb  (as above)
#       enable_uart=1
#     (add core_freq=400 to pin the core at 400 MHz instead of
#     enable_uart's implicit 250, preserving vc4/HDMI bandwidth;
#     both variants board-verified)
#   * option 2 (DEFAULT, active below): PL011 on the GPIO header
#     = /dev/serial0 (ttyAMA0, console), onboard BT on the
#     mini-uart @921600, presented as hci0 (no /dev/serial1 node
#     while the serdev BT owns the port)
#   * option 3 (BT off): uncomment dtparam=smartedge_bt=off (with
#     the default DTB the mini-uart then shows up as a plain
#     /dev/ttyS0 on GPIO32/33; serial0 stays on the PL011)
#
# NOTE: Only one of these options should be enabled at one time
#################################################################
